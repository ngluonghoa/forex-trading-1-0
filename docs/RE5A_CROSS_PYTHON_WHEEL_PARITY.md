# RE5a — Cross-Python wheel byte parity and exact packaged-source audit

**Bounded step:** from RE4c2 post-docs main `c59fe0ef82c327a88a6723fc88faa36ba35556af` (2026-11-08). This is a read-only CI evidence improvement, **not** a release, a signed attestation, an approved last-known-good build, or authorization to trade. The source of truth remains native 00 Handoff, 06 QA and 10 Release Standard; 02 Master Spec v0.11 §26 must remain unchanged.

## Decision and threat model

Existing RE3/RE4c2 CI builds a wheel twice on **each same runner** and verifies byte equality; the same SHA across Python 3.11/3.12 was only manually observed in separately read logs. RE5a adds a blocking **independent cross-Python job**, within the **same GitHub Actions run**, to mechanically compare artifacts. It also checks that **every packaged Python file's bytes** match the exact checked-out `src/forex_trading` source and that no additional Python modules are packaged. A copied or stale wheel that matches the other interpreter's wheel but not the current source fails.

- Each matrix job still runs the complete 547+ existing synthetic tests, Ruff/mypy, tracked and historical high-confidence secret scans, Bandit, app/build advisory pip-audit, same-runner repeat SHA parity. Only after passing, upload exactly one CI wheel as artifact `forex-re5a-wheel-3.11` or `forex-re5a-wheel-3.12` in that workflow run.
- GitHub actions/upload-artifact pinned to official commit `ea165f8d65b6e75b540449e92b4886f43607fa02` (v4.6.2) with `if-no-files-found: error`, explicit wheel glob, hidden directory allowance, one-day retention. No upload to PyPI, releases or external account. GitHub actions/download-artifact pinned to official commit `d3f86a106a0bac45b974a628896c90dbdf5c8093` (v4.3.0). This extra GitHub Actions artifact transfer and short verification job can consume CI minutes and transient artifact storage.
- Downstream `cross-python-wheel-parity` job requires both matrix jobs success; downloads only named artifacts **from current workflow run** and checks exactly one .whl per Python artifact, same wheel filename, expected `pyproject.toml` name/version, packaged Python inventory, source bytes, and matching SHA-256 wheel digests. Missing, duplicate, renamed, altered or unsafe ZIP packages fail closed. It prints `CI_CROSS_PYTHON_WHEEL_PARITY_PASS` with both Python labels, wheel SHA and source module count. Additional synthetic tests include negative stale source, changed wheel contents, hidden .py, ZIP traversal, duplicates and wrong version.
- The already pinned PEP 517 backend `setuptools==84.1.0`, app runtime deps=[], older security gates and all user-facing Forex contracts are unchanged. No user Mac, Desktop Commander, live Google Drive cache, market data provider or broker is accessed.

## Bounded assurance and explicit gaps

This demonstrates **byte-for-byte parity of two separately built wheels (Python 3.11 and 3.12) within one GitHub-hosted run**, source-content consistency against the checkout, and exact metadata for those wheel artifacts. It is **not a cryptographically signed SLSA/in-toto supply-chain attestation**, not trusted off-GitHub reproducibility, does not make an artifact reproducible across OS/hosts/dates, does not pin every transitive package with hashes, has no hardware-backed release signing, SBOM, administrator-approved release/LKG or production rollback drill. Uploaded Actions artifacts are untrusted build outputs, not release distributions.

**Acceptance proof required after implementation:** distinct Python 3.11 and 3.12 source/CI matrix jobs PASS old and new tests, upload artifacts available to downstream cross-Python check, cross job PASS verified byte digest and source count, reviewed narrow PR, independent merged-main Actions matrix plus cross job PASS, then update native 00/06/10 and do a separate exact Handoff docs-only snapshot PR.
